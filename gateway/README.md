# Lab VPN Gateway

> Deprecated / abandoned.
>
> This directory is kept only as an experiment record. We are not using the
> OpenVPN gateway approach now. The active approach is the SSH SOCKS runner
> generated by `server.py`.

Docker-based OpenVPN gateway. Devices import an `.ovpn` profile and send all
traffic through the lab server, similar to using the server as a remote hotspot.

WireGuard was the first choice, but this CentOS 7 server kernel does not support
WireGuard interfaces. OpenVPN runs fully in Docker with `/dev/net/tun`, so it is
the practical Docker-first gateway here.

## Files

- `config.json` - all settings and client list.
- `docker-compose.yml` - runs the gateway container in host networking mode.
- `state/` - generated keys and client configs, created on first start.
- `scripts/start.sh` - build and start.
- `scripts/stop.sh` - stop.
- `scripts/status.sh` - show WireGuard status.
- `scripts/show-client.sh` - print the `.ovpn` profile selected by
  `export_client` in `config.json`.

## Server

```bash
cd ~/serverfetch/gateway
./scripts/start.sh
./scripts/status.sh
./scripts/show-client.sh
```

Open UDP `1194` to the server if a firewall blocks it.

## Clients

Install OpenVPN Connect:

- iOS / Android: OpenVPN Connect app, import the `.ovpn` profile.
- Windows / macOS: OpenVPN Connect desktop app, import the `.ovpn` shown by
  `show-client.sh`.

Default clients:

- `phone` -> `10.66.0.2`
- `laptop` -> `10.66.0.3`

To add a client, edit `config.json`, add a new entry under `clients`, set
`export_client` to the client you want to print, then run:

```bash
./scripts/start.sh
./scripts/show-client.sh
```
